# API Limits and Webhooks

## Rate limits
Each API key is limited to 100 requests per minute. When a key goes over the limit, the API answers with HTTP 429 and includes a Retry-After header that tells your client how long to wait before sending the next request. Clients should respect this header instead of retrying immediately.

## Webhook delivery
If your server does not accept a webhook, Nile Wallet retries the delivery 5 times with exponential backoff, within 24 hours. Make sure your endpoint returns a success status quickly so that events are not retried unnecessarily.

## Verifying webhook signatures
Every webhook carries the header X-NileWallet-Signature, which is an HMAC-SHA256 signature of the request. Verify it on your side before you trust the content of an event, and reject any request whose signature does not match.

## Sandbox and idempotency
You can test your integration in the sandbox at sandbox.api.nilewallet.example without touching real money. For requests that create something, such as a payment, send an Idempotency-Key header. The key is honored for 24 hours, so repeating the same request with the same key during that time does not create a duplicate.
